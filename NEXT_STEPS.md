    **Final-residual guard.** A solve whose assembled solution leaves any equation's residual above `max(1e-6, 100·rel_tolerance)`, relative to that equation's own top-level terms, now fails with the equation quoted instead of reporting `ok` (`engine::unconverged_equation`, applied in `PreparedDocument::assemble_solution` for solve, sweep rows and all-roots). This is the path by which the merge rescue once returned a 1.2e4 residual as success. Across the 843 converged corpus solves the worst relative residual is 1.3e-7, so no golden changes.

    **DYNAMIC unit check (2026-10-22).** `DYNAMIC` bodies and their scalar initial conditions now reach the unit checker in `check`, the prepared solve and the ODE-only shortcut, through one helper (`engine::unit_check`).
    - `der(X)` carries X's units per second when X has real units. For a dimensionless state, whose model is unitless, it stays a wildcard.
    - A bare-number initial value (`x(0) = 0`) declares nothing.
    - The time variable is a wildcard.
    - `If(...)` now carries its branch units instead of reading as dimensionless.
    - Method-of-lines `FOR` blocks and array-state initials are checked too (2026-10-23, see the fifth paragraph below).

    The check exposed one library defect. SigPID's clamped anti-windup was `der(ie) = e + (out.sig - u_raw)/Taw`, which balances only with Taw in output-per-measurement units. It is now `/(Ki·Taw)`, so Taw is a reset time in seconds (owner decision 2026-10-22). Every affected example states `Taw = old/Ki`, so results are unchanged. `ev-battery-cooling-pid`'s input changed with provenance, and its expected output did not. It also exposed bare component parameters in 2 Help examples, 4 reference pages and 2 gallery models, which now carry units.

    **Component parameter units (2026-10-22).** A component header's `Resistor(R [ohm])` unit now reaches `components::def::Param`. A bare instance value under it is typed for the checker (`R=10` is 10 Ω), never scaled. 255 parameters of 105 components in `library-data/` declare the units their reference pages stated. `parse-library.mjs` reads them, so the header is the wizard's unit source, and the generated catalogs did not change. No example warned. One test had pinned the Java engine's false "right side [A]" warning on an untyped resistor; it now asserts none.

    **Table and plot checklist audit (2026-10-23).** The September reviews (T1–T15, F1–F12; recovered from `0b116de^:docs/`) were walked item by item against the code, not test titles. All fifteen table items and eleven of the twelve plot items were already fixed and pinned by a test, mostly in `tables.precision.test.ts`, `tableValidation.test.ts`, `tableGridModel.test.ts`, `csv.test.ts`, `composeTables.test.ts`, `solve_table.rs` and the `plots/` suites. One hole remained: F8's shared Y-axis label dropped unknown units, so a `kPa` series beside an unknown-unit one labelled the axis `[kPa]`. Fixed in `PlotCard.tsx`, pinned in `plots/data.test.ts`. The right Y axis was linear-only with no log control; it now has one (`format.y2Log`, the plot dialog's Log Y2, `y2log` in a PLOT block; 2026-10-23). T3 now has an App-level test as well; see the cross-layer paragraph below.

    **Method-of-lines unit check (2026-10-23).** `FOR` blocks inside `DYNAMIC` and array-state initials (`T[2](0) = T_init`, `T[1:N](0) = …`) now reach `engine::unit_check`. Loop bounds such as `N` are solved values, unknown at check time, so each loop body is lowered once rather than expanded (`MolArrays`). An array indexed anywhere by something other than a literal is one field and reads as a single variable, so the boundary `T[1] = T_left` and the initials ground the loop body. An array indexed only by literals keeps one variable per element, because a state vector may mix position and velocity. A loop variable reads as a dimensionless 1. Pinned by `method_of_lines_bodies_and_array_initials_are_unit_checked`; all 809 doc blocks still check at zero unit warnings.

    **Component parameter descriptions and units (2026-10-23).** The 162 component pages with two-column parameter tables now have three, each parameter described from the component's own equations, and their library headers declare the units: 489 newly typed parameters, dimensionless ones as `[-]`. BatteryCellMap's page also gains the four header parameters it had dropped (`R1`, `C1`, `k_cal`, `Ea_cal`). A parameter whose unit depends on its wiring stays untyped and says so on its page: signal levels and gains; Economizer's `lim` and `band`, which are K or J/kg by variant; and the signal time parameters that meet `time` or an untyped gain (SigSine `freq`, SigStep/SigRamp/SigPulse `t0`/`width`/`eps`, SigRateLimiter and SigPID `tau`). Typing those made three reference examples warn, because a steady document pins a bare `time = 0.125` and bare gains read dimensionless. Pure filters keep `[s]` and `[rad/s]`. All 809 doc blocks check at zero unit warnings, and the regenerated catalogs only gain units and descriptions.

    **Cross-layer acceptance (2026-10-23).** Two journeys in `e2e/phase9-journeys.spec.ts` drive the built app:
    - Journey 4 takes a °C model with a code plot through edit, solve, the plot window, SVG export, Save Project, New Project, Open Project and a second solve. The FS Access pickers are removed first, so the download and file-input fallbacks are what runs.
    - Journey 5 edits the document while a solve is still busy and asserts the stale result never surfaces. It covers the document path. T3's table path is pinned in `src/tableSolveRace.test.tsx` (2026-10-23): the real App, with the engine stubbed one layer below `api.ts`, runs a table solve, takes a workbook edit while it is in flight, and discards the late result. A late table result is now also discarded on any change to the table's inputs (`sameParamInputs`: columns, row ids, typed values), not only on a revision change. Before this a value edit was caught only by the revision bump, so an edit path that skipped `setTables` would have let the stale result back in. No current path skips it; the comparison makes that independent of every caller. The same file pins a second race found while chasing a CI failure on #59: a desktop Solve (button or F2) pressed while a check — including the idle live-lint — is still running was dropped with no feedback, because `checkThenSolve` returned on `checking`. It is now queued and runs when the check lands (`solvePendingRef`); the phone layout already disabled Solve during a check. The CI failure itself was the journeys' `setEditorContent` clicking Solve before the typed keystrokes had landed on a loaded runner; it now waits for the document's last line. F2 in a table view had the same gap against a table check (`checkThenSolveTable` returned on `checkingTableId`); it is queued the same way (`tableSolvePendingRef`, 2026-10-23). The top bar's table Solve was never affected: it calls `onSolveTable` directly and skips the check gate by design. Journey 5's solve now runs about twice as long as landing its edit needs, and the edit swaps in a one-line document so the follow-up solve is instant. The cross-browser e2e now runs as its own CI job (`e2e`) inside `mcr.microsoft.com/playwright:v1.62.1-noble`, on the `dist` the web job uploads: `playwright install --with-deps` went through apt and hung on the Azure mirror three times on 2026-10-23 (40 min, then twice into a 10-min cap) before any test ran. The image tag must track the locked `@playwright/test` version. The same suite passed in that image locally, WebKit included (29 passed, the known WebKit offline skip).

### Native desktop & iOS (Tauri v2) — proposal only

No Tauri project exists and no build has been measured.

**Why the port is cheap:**

- There is no cross-origin isolation or network dependency.
- The engine boundary is already `&str → String` (`crates/frees/src/lib.rs`), and `frees-cli` already calls it natively.
- `call(...)` in `engineClient.ts` is the single dispatch seam.

**Hard constraint — thread affinity.** The REPL session, progress sink and deadline predicate are `thread_local!`, so the native side needs one dedicated `std::thread` per worker index, with index 0 REPL-affine. A Tokio blocking pool would lose the session.

**Phases:**

1. `src-tauri/`, excluded from the root workspace (or the wasm32 clippy gate breaks). CSP keeps `'wasm-unsafe-eval'`.
2. A `tauri` Vite mode without the PWA/build-info plugins, with `base: './'`. Keep `legacy-peer-deps`.
3. Per-index engine threads, with `ipc::Channel<f64>` for progress. Use the JSON envelopes, not `*_zerocopy`.
4. One `saveBlob` helper replacing the six anchor-download copies; `openPrintReport` is the hardest item.
5. A `build-tauri` release matrix, unsigned.
6. iOS, which needs macOS/Xcode.

**Accepted ceilings:**

- JSON envelopes, not binary IPC.
- Stop cancels only transients.
- The `localStorage` quota is unchanged.

**Acceptance:**

- Every §4 gate stays green unchanged.
- A dispatch-layer test covers every method name.
- Manual smoke: solve parity, sweep progress, Stop, two-call REPL affinity, exports, reopen, print.
