# Schematic workspace — design handoff

Design draft delivered: 2026-10-28. Companion to [CR-SCHEMATIC-01](schematic-workspace-change-request.md). This is a reviewable design proposal, not a production implementation or a claim that all acceptance tests have passed.

## Open the design

[Start with the Figma review index](https://www.figma.com/design/SHIyfVVicYxMCbXqzedk8Z?node-id=77-3). The page is **12 · Proposed schematic workspace**, separate from the existing captured screens. Use Figma Present to follow the desktop, tablet or review flow starting points.

The deliverable contains **27 editable frames/boards**, including the index, plus a reusable schematic component board. It covers all 65 functional requirements with screens, controls or explicit behavioral annotations. It includes 977 cross-screen prototype reactions with no unresolved destinations. Same-screen controls such as typing, dragging, scrubbing and toggles are illustrative states; Figma does not execute arbitrary model operations.

Confirmed scope: all current engineering domains and equation/variable visualization; hybrid engineering symbols with optional result cards; full desktop and tablet authoring; no phone layouts.

## Recommended product direction

Keep FREES' solver, language, editor, Mantine conventions, Dockview and local project storage. Add a stable Library/Model tree, one selection inspector and Problems/Watch/Run drawers around a readable canvas. Selection preserves surrounding context. Source navigation is explicit. Typed port pickers provide an alternative to dragging on desktop, touch and keyboard.

Semantic editing must operate on the existing source through validated, scoped transactions. Presentation settings have a separate persisted document and never change the equations or invalidate results. The source/engine metadata work in change-request section 7 is a prerequisite for safe rename, delete, reconnect and subsystem extraction. A visual-library replacement alone will not solve this.

## Component and responsive contract

Use the existing Mantine dark/light variables and Roboto/Fira Code styles. Local reusable variants cover Button, IconButton, Mode switcher, View switch, Field, Badge, Node, Port, Library item and Data row. Symbol instances use the repository's engineering SVG assets. The local component board is [editable in Figma](https://www.figma.com/design/SHIyfVVicYxMCbXqzedk8Z?node-id=79-13).

- **Canvas toolbar.** One row: breadcrumb, Undo/Redo, Mode switcher (Select, Pan, Connect, Probe, Note), Add, Arrange, View, then View switch (Source/Split/Schematic), Find, Engineering and Export. The separate navigation row is gone; the canvas takes the height.
- **Nodes.** `Style=Symbol` is the default on authoring canvases: the engineering symbol leads, with name and one result line. `Style=Card` remains for results, diagnostics and hierarchy views where type and value text matter. Both styles share a footprint, so switching representation does not move ports.
- **Ports.** Shape and colour both encode domain, so colour is never the only cue: fluid circle (cyan), thermal square (pink), electrical diamond (orange), rotational triangle (lime), signal arrow (violet).
- **Badges.** Tinted pills, separate from buttons. Run status always names the run ("Solved · Run A", "Stale · Run A"); a stale node keeps its last value and the badge, not a text prefix, carries staleness.
- **Destructive commands** (Disconnect, Disconnect & Check, Delete) use `Button State=Danger`.
- **Instance name.** Renaming an existing instance is a scoped refactor (SYNC-04), so it is a "Rename…" command beside Source and Definition rather than an inline field. Inline name fields appear only where a new instance is being created (25, 21).
- **Library.** Dense rows: symbol, name, one-line description and a meta line (ports or domain).
- **Node compact.** For large models (the names-and-symbols preset): a 108 × 48 node with symbol, instance name and one result, labels at 12 px or larger at 100% zoom. Frame 19 fits all 26 EV instances in an 1140 px canvas this way; the type and full readouts move to the inspector. `Size=Chip` (24 px high, width hugs the label) is the level of detail at Fit for about 100 components: symbol, label and at most one result, with ports and parameters shown from 100 % zoom or on selection. Frame 26 fits 100 instances in the same canvas with 12 px labels; its envelope links use a named net (`OUT`) instead of 16 long wires.
- **Menu item** and **Tree row.** Menus and context menus use menu rows with a right-aligned shortcut, a Danger state for destructive commands and a Disabled state that says why. The model tree uses tree rows with disclosure chevrons, depth indent and a dimmed type, and highlights the scope the canvas shows.

The primary mockup uses compact 216px/300px docks to leave enough canvas at 1440px; the proposed 240px/320px implementation defaults remain resizable. Use available pane width to collapse docks. Wide desktop is 1920×1080; standard desktop is 1440×960; tablet examples are 1024×768 and 768×1024. On tablet, keep the full command set, open one detail surface at a time and use at least 44px interaction targets. Portrait provides editable component/connection lists; it is an authoring surface, not a read-only fallback. Tablet links may open shared desktop design examples to explain the next workflow; these links do not establish responsive runtime behavior.

Do not copy Figma's sample source snippets or illustrative multi-domain labels as validated engine fixtures. Frame 19 is the exception: it draws `EV_THERMAL_EXAMPLE_TEXT` (`web/src/defaultExample.ts`) with its 26 instances, 25 connection sets and the Run A values from `frees-cli solve` at `51a2ea2`. Redraw it if the example changes. The humid-air frames show the frees-cli solution of the document in frame 06 (`eff_hp = 0.45`, `W = 0.011`, FAN `eta = 0.55`): HP Q 3.60 kW, COIL Q 7.01 kW, FAN W 228.77 W, supply 292.24 K, 67.25 % RH, humidity ratio 0.00928. Frame 12's Run B (`eta = 0.60`) gives 209.70 W; its temperature trace is still illustrative, because the model is steady and the two run values are steady supply temperatures. Frame 16's `heat-balance.frees` is a separate, illustrative equation document. Frame 26 draws a 100-instance model built only from library components; `web/e2e/schematic-baseline.spec.ts` builds the same document as `DENSE_FLOOR`, and its values are Run A from frees-cli at `51a2ea2`. Humid-air port labels use the `pre_in`, `pre_out`, `re_in`, `re_out` interface. Advanced variant/map examples and transient curves communicate interaction structure; available fields, numerical values and connection contracts must come from the real engine/catalog.

Mode, view-switch, Undo/Redo and Export controls link to the frame that demonstrates them; 04's port popover and 06's Apply/Cancel complete their flows.

Frames 02, 12, 13, 18 and 20 were inspected during review and changed only by text substitutions afterwards; so were the humid-air value updates in 01, 03–07, 09–12, 15 and 22–24. - Inspected representative screenshots for desktop, tablet landscape/portrait, light theme, advanced configuration, symbol editing, hierarchy, net semantics and the review index. Fixed overflowing panels, wrapped-text clipping, icon fills, scaled-symbol geometry and example topology inconsistencies found during review.
- Small accent text uses schematic-specific light-mode values instead of altering the captured atlas palette. Measured accent contrast is approximately 5.0:1 on white and 4.5:1 on the light canvas; cyan text is approximately 5.6:1 on white and 5.0:1 on the light canvas. This is a token spot-check, not full WCAG certification.
- Requirement-manifest self-check verifies all 65 IDs occur exactly once and all referenced frames exist.
- Repository research baseline remains 101 passing tests in seven schematic test files under Node 24. No production code changed during mockup creation, so the application suite was not rerun solely for documentation/Figma edits.
